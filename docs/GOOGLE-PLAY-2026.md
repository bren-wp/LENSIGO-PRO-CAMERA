## Before Google Play upload

1. Securely sign **release AAB** with your Google Play upload key; debug APK is not an accepted substitute. Never commit signing keys, certificates with private keys, keystore passwords or .env secrets.
2. Check package name, versionCode uniqueness, release track, Play App Signing and **16 KB page support**. Inspect the final signed AAB and APKs generated by bundletool for all ABI variants.
3. Complete Play Console Data Safety declaration based on actual behavior and transitive SDKs, privacy policy availability, app content classification, content rating, target audience, and data access / permission declarations.
4. Use original screenshots of functioning Android UI (1080x2400 phone, 1600x2560 tablet as applicable), real store icons/feature graphic and truthful metadata. Static design mockups are not proof of functioning screens.
5. Run a pre-launch report, emulator tests (Android 7/9/10/12/16/17) and tests on physical devices including low RAM / vendor CameraX.
6. Inspect all dependencies and packaged libraries with Play SDK Index, dependency graph and vulnerability audit; CI lint is not a security certification.
7. Do not declare the application production ready solely because assembleDebug/bundleRelease pass or a GitHub prerelease exists.

### Native libraries and 16 KiB gate

Current CameraX / AndroidX dependency graph includes `libimage_processing_util_jni.so`, `libsurface_util_jni.so` and `libandroidx.graphics.path.so`. CI validates the **ELF LOAD segments of 64-bit builds** and that uncompressed APK native libraries begin at 16 KiB-aligned payload offsets. Unlike the first conservative check, the presence of any `.so` is not itself a failure. Any actual alignment failure blocks release and must be fixed upstream or by rebuilding the library; do not simply disable the check. Verify a signed AAB using bundletool/Play Console too.
